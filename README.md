# Home Lab Notes - инжинерные дневники по поводу всяко-опса на уровне домашней лаборатории.

## Преамбула

Был у меня настольно-подстольный "домашний сервер", на Ubuntu, на который я наладил ssh, поставил докера и т.п., и запускал там docker compose-ом "всякие штуки" для обучения и развития.

На одном из учебных проектов надо было развернуть два Kafka-кластера, для демонстрации репликации, рядом недокластер Spark-а, контейнеры с рсубд, сервисами мониторинга и т.п. Я срочно докупил RAM с 32-х до 96-ти, поназадавал ограничений контейнерам на память в compose, и имитировал эту "почти как взрослую" конфигурацию.

Но Кафка-кластеры я разделил (кроме идентификаторов кластера) через прописывание разных докер-сетей в определениях сервисов компоуза, и задумался о том, что конечно хотелось бы разместить их на трёх домашних машинах (как получилось однажды в прошлом, когда "игрался" с Hadoop). Но знакомые сисадмины мне сказали: тебе достаточно виртуальных машин. И я подумал: действительно! виртуальные машины!

И вместо Ububtu поставил Proxmox VE. Почему его? "По совету знакомых сисадминов": комфортное управления Гостями через веб-интерфейс; то есть критерий - удобство для домашней лаборатории, при том, что это гипервизор 1-го типа (Bare Metal Hypervisor), имелось ощущение, что порог входа для меня будет более низким по сравнению с аналогами.

Так же уже на тот момент я поверхностно познакомился с LLM-ками, и у меня возникли мысли по поводу организации локального инференса LLM на этом же домашнем сервере.

Я купил видеокарту RTX 3060 12GB (посовещавшись с нейросетками на предмет минимально необходимого, но максимально бюджетного варианта), и задача домашнего сервера немного расширилась: я захотел использовать гипервизор, чтобы поднимать виртуальные машины и LXC-контейнеры не только для "всяких датаинжинирных дел", но и для всяких дел по изучению "нейросетей и всякого такого новомодного".

По дороге я узнал, что существует такой формат как "инженерные дневники", узнал слово "HomeLab" и т.п., и вместо записей в домашнем телеграм или файлах, обсидиане и т.п., задумал лить всё в гитхаб.

Предварительная структура будет какая-то такая, опять же по предложению нейросетки, а там посмотрим:

```
├── README.md                   # Главная страница: архитектура лабы, железо, навигация
│
├── infrastructure/             # Базовый уровень (Виртуализация и Сеть)
│   ├── proxmox-setup/          # Тюнинг Proxmox (проброс GPU, LXC vs VM)
│   └── network/                # Локальный DNS, балансировщики (Nginx/Traefik)
│
├── ai-ops/                     # Локальный инференс и LLM
│   ├── vllm-benchmarks/        # Кейс: развертывание vLLM, замеры токенов в секунду
│   ├── ollama-containers/      # Кейс: Ollama в Docker/LXC, интеграция моделей
│   └── multi-agent-systems/    # Эксперименты с CrewAI / Autogen
│
├── data-engineering/           # Платформа данных (Data Platform)
│   ├── kafka-cluster/          # Брокер сообщений (IaC/Docker манифесты)
│   ├── spark-processing/       # Локальный Spark для тестов
│   └── databases/              # Vector DBs (Chroma/Milvus) и SQL/NoSQL
│
└── research-rag/               # Прикладные кейсы (Стыковка AI и Data)
    └── local-rag-pipeline/     # Кейс: Интеграция Spark -> VectorDB -> vLLM
```

В целом эта репа про всё то же, чем я занимался дома в последние годы (сам себе я называю это "Езучение и Авладевание всяко-опс-штуками"), но только теперь вместо/сверх stackoverflow и т.п. у меня в компаньонах ЛЛМ-ки, а заметки попадают сюда, а не теряются в телеграм-чатах и файлах блокнота.

Первые заметки, как раз про Proxmox и первый контейнер, больше написаны Курсором по нашим с ним работам и моим сумбурным сопроводительным записям, далее будет больше человекописания и соотв. человекочитаемости.

## Разработка и коммиты

В git не попадают реальные IP, пользователи и имена ZFS — см. `private/map` (локально, не в git). Pre-commit **только на вашей машине** (нужен каталог `private/`); в GitHub CI проверка не запускается.

```bash
pip install -r requirements-dev.txt
pre-commit install
pre-commit run --all-files
```

Паттерны утечек — в `private/leak-patterns.conf`; публичная обёртка `scripts/check-no-private-leaks.sh` без боевых значений.
